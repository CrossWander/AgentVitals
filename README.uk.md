Програма в треї Windows для Claude Code, Codex, GitHub Copilot і Cursor. Вона показує, скільки
лишилося від квоти кожного агента і коли її буде скинуто, що просто зараз робить кожна сесія
Claude Code чи Codex, скільки сьогоднішня робота коштувала б за цінами API і чи працює сервіс агента.
Сповіщення попередить, поки квота не скінчилася, коли агент закінчить довгий хід і коли він попросить
дозволу. Кожен агент, у який ви увійшли, має свою вкладку. Зроблено за мотивами
[ClaudeBar](https://github.com/tddworks/ClaudeBar) і
[claude-status-bar](https://github.com/m1ckc3s/claude-status-bar) — вони роблять те саме на macOS.

## Швидкий старт

1. Завантажте `AgentVitals.exe` з [останнього релізу](https://github.com/CrossWander/AgentVitals/releases/latest).
   Потрібен [.NET 10 Runtime](https://dotnet.microsoft.com/download/dotnet/10.0). Інсталятора немає:
   exe запускається з будь-якої теки.
2. Запустіть його. У треї з'явиться значок із пульсом. Windows 10 може сховати його в приховану
   область — один раз перетягніть його на панель завдань.
3. Кожен агент, у який ви увійшли, одразу показує свої квоти, на своїй вкладці — див.
   [Агенти](#агенти). Щоб бачити живі сесії, відкрийте [вікно «Агенти»](#вікно-агенти), виберіть
   Claude або Codex і натисніть **Підключити** в розділі *Живі сесії*.

Наведіть мишу на значок — з'явиться коротка картка, клацання відкриває все вікно, клацання правою кнопкою —
меню. Вікно лишається відкритим, поки ви працюєте в інших вікнах: закривається ✕, ще одним клацанням
по значку або Esc. На малому екрані воно не виходить за його край: заголовок і кнопки стоять на
місці, а середина прокручується.

## Налаштування

налаштування: мову, вигляд, як часто перевіряти квоти, рівні «важливо» й «критично», сповіщення

## Агенти

| Агент | Звідки дані | Стан |
|---|---|---|
| Claude | `GET api.anthropic.com/api/oauth/usage` з токеном Claude Code з `~/.claude/.credentials.json` | працює |
| Codex | `GET chatgpt.com/backend-api/wham/usage` з `~/.codex/auth.json`; пошта акаунта — з його `id_token` | працює |
| Gemini | запити квот `cloudcode-pa.googleapis.com` з `~/.gemini/oauth_creds.json` | не перевірено |
| Copilot | `GET api.github.com/copilot_internal/user` із входом GitHub, який git зберігає в «Диспетчері облікових даних» Windows (`git:https://github.com`) | працює |
| Cursor | `GET cursor.com/api/usage-summary` із входом, який Cursor зберігає у своєму `state.vscdb` (лише читання): план із частками Auto та API й витрати понад нього — свої або командний пул | не перевірено |

Агента без файлу входу просто немає у вікні. Copilot з'являється лише після того, як GitHub хоч раз
його підтвердив: Copilot Chat іде разом із VS Code, тож його тека сама по собі нічого не означає.

Якщо Claude Code зберігає вхід у «Диспетчері облікових даних» Windows, AgentVitals читає його й
звідти та бере той із двох, що діє довше (не перевірено).

## Акаунти

AgentVitals запам'ятовує кожен акаунт агента, у який ви входили, — користувача Claude в організації,
акаунт ChatGPT у Codex, логін GitHub у Copilot, користувача Cursor. Коли сесія скінчилася і ви
перемкнулися через `/login`, попередній акаунт лишається на вкладці зі своїми останніми цифрами, і
видно, коли він звільниться.

| Світла тема | Темна тема |
|---|---|
| <img src="docs/accounts-light.png" width="360" alt="Картка акаунтів, світла тема"> | <img src="docs/accounts-dark.png" width="360" alt="Картка акаунтів, темна тема"> |

- **Акаунт у роботі** — той, чий вхід зараз в агента. Лише в нього свіжі цифри, лише він фарбує
  значок у треї й шапку і лише про нього сповіщення про квоти. Після `/login` AgentVitals бачить новий
  акаунт за секунди, позначає його «цифри оновлюються…» й одразу питає сервер; пауза після 429 — у
  кожного акаунта своя, і попередній не затримує новий.
- **Картка «Акаунти»** з'являється під картками квот, коли в агента два акаунти й більше: акаунт у
  роботі першим, інші в порядку появи, у кожного — тариф, вік цифр і смужка на кожен ліміт. Видно
  три, решта прокручується всередині картки.
- **Клацання по акаунту** показує його в картках угорі з позначкою, що це останні цифри, які бачив
  AgentVitals. Щоразу, як вікно відкривається, угорі знову акаунт у роботі.
- **Плашка** каже «у роботі», «сесія — через 1 год 10 хв» або «тиждень — з вт 09:00», поки ліміт
  запам'ятованого акаунта вичерпано (той, що скинеться останнім), «знову доступний» — коли відтоді
  скинулися всі, і «вільний» в інших випадках. Сповіщення скаже, коли запам'ятований акаунт знову
  доступний; клацання відкриває його вкладку з ним угорі.
- **Імена.** Акаунт називається поштою (у Copilot — логіном GitHub); у двох акаунтів з однією поштою
  додається тариф. Під оком — «Акаунт 1», «Акаунт 2». Свої імена задаються у
  [вікні «Агенти»](#вікно-агенти) і видні й під оком.
- Статистика витрат і живі сесії спільні на всі акаунти агента: у журналах агентів не сказано, яким
  акаунтом ішла робота.

AgentVitals сам акаунти не перемикає й токенів не зберігає: він пам'ятає лише тариф, пошту, відсотки
й номер акаунта з файлів самого агента.

## Вікно «Агенти»

Кругла кнопка з роботом у кінці рядка вкладок або *Агенти…* в меню правої кнопки миші відкривають
звичайне вікно — воно є на панелі завдань, рухається й не закривається само.

| Світла тема | Темна тема |
|---|---|
| <img src="docs/agents-light.png" width="360" alt="Вікно «Агенти», світла тема"> | <img src="docs/agents-dark.png" width="360" alt="Вікно «Агенти», темна тема"> |

- **Список** показує агентів у порядку вкладок: номер — місце вкладки, воно ж Ctrl+N. **▲ Вище** і
  **▼ Нижче** рухають вибраного агента. Незнайдені агенти — унизу, сірі.
- **Перемикач** вимикає агента: його не питають, у нього немає вкладки, сповіщень і впливу на значок;
  hooks лишаються на місці. Увімкнули — усе повернулося одразу.
- **Праворуч** — подробиці вибраного агента: стан, [живі сесії](#живі-сесії) з кнопками
  **Підключити** й **Відключити** та його акаунти — поле імені (пошта — у підказці, око її ховає),
  тариф, останні цифри й **Забути** в запам'ятованого.

## Квоти й сповіщення

- **Картки.** Кожне вікно квоти — картка з відсотком витрат, смугою й часом до скидання. Вікно на
  100% пише «вичерпано». Додаткові витрати показуються, якщо їх увімкнено: extra usage у Claude,
  витрати понад план у Cursor. Картки йдуть парами; на вкладці лише з квотами — без статистики й
  сесій, як у Copilot і Cursor, — кожна картка на всю ширину.
- **Темп.** На смугах сесії й тижня (і тижнів за моделями) стоїть позначка — де були б витрати за
  рівного темпу, а картка пише «у нормі» або «із запасом» (у межах 5 пунктів — у нормі). Якщо
  витрати випереджають темп, картка пише, коли вікно скінчиться, якщо продовжувати так само:
  «вистачить до 15:40» або «вистачить до чт 14:00» для тижня. Підказка над карткою пояснює позначку
  обома числами.
- **Кольори.** Лінія пульсу в треї бере колір вікна, що обмежує найсильніше: зелений нижче рівня
  «важливо», жовтий від нього, червоний від «критично», сірий, коли даних немає. Це ті самі рівні,
  що й у сповіщень, тож червоніє те, про що попереджали; картки, смуги й заголовок слідують їм також.
  Заголовок вікна говорить за відкриту вкладку, а вкладка, чий агент на межі, отримує крапку цього
  кольору. Вичерпаний тиждень фарбує значок у червоний і за порожньої сесії.
- **Сповіщення.** Коли вікно доходить до 75% («важливо», лишилася чверть) і 90% («критично», майже
  вичерпано), з часом до скидання. Обидва рівні змінюються в налаштуваннях кроком 5 від 50% до 95%.
  Кожне сповіщення приходить один раз і знову — лише після скидання цього вікна; вікно, що вже за
  рівнем під час запуску AgentVitals, теж отримує сповіщення. Сповіщення ще пише, до якого часу
  вистачить залишку за такого темпу, якщо це раніше за скидання. Частки Auto та API в Cursor —
  частини його місяця, власних сповіщень у них немає.
- **Звук для «критично».** *Звук, коли квоту майже вичерпано* додає тихий дерев'яний стук, дві ноти
  вниз, лише до сповіщення «критично» — типово вимкнений. Він не схожий на висхідний дзвін запиту
  дозволу, тож їх можна розрізнити, не дивлячись.
- **Ранні сповіщення й сповіщення про скидання.** Від половини витрат і нижче «важливо» — одне
  сповіщення на вікно, якщо за такого темпу його не вистачить до скидання («Не вистачить до
  скидання»). Після сповіщення «критично» — ще одне, коли вікно скинеться («Знову доступно»), у
  межах хвилини від часу скидання, не чекаючи наступної перевірки.
- **Як виглядає сповіщення.** Воно виїжджає в правому нижньому куті над годинником і тримається
  десять секунд для квоти чи сесії й чотири для статусу сервісу — і весь час, поки на ньому миша;
  блідий ✕ у куті закриває його одразу. Воно з'являється поверх вікна AgentVitals, якщо те відкрите.
  Клацання по сповіщенню про сесію піднімає вікно, у якому йде сесія, а по будь-якому іншому —
  відкриває вікно AgentVitals. Кожне сповіщення записується й у `log.txt`.

Квоти типово перевіряються кожні 5 хвилин (1, 2 або 10 хвилин у налаштуваннях; що частіше, то
раніше сервер відповість 429). Після 429 AgentVitals чекає стільки, скільки сказав `Retry-After`, а
якщо відмови йдуть поспіль — довше: 5, 10, 20, потім 30 хвилин. Після нічного сну токен Claude Code
зазвичай минув: картка тримає останні цифри й чекає, крім вікна, чий час скидання минув, — воно
показує 0% і «скинуто» (витрати з інших пристроїв відтоді не видно, поки не прийдуть свіжі дані).
Claude Code оновлює вхід під час першого запиту, а AgentVitals помічає новий файл і одразу питає.

Остання відповідь зберігається в `quota.json`, тож після перезапуску картка одразу показує її з віком
(«Оновлено 3 год 10 хв тому» або «Оновлено пт 18:40» після вихідних). Сервер питають знову лише
тоді, коли від цієї відповіді минув інтервал, і не раніше часу, який він назвав в останньому 429:
перезапуск AgentVitals більше не витрачає ліміт запитів і не отримує відмову одразу.

## Живі сесії

Вікно «Агенти» → Claude → *Живі сесії* → **Підключити** додає hooks AgentVitals у
`~/.claude/settings.json`.
Кожен hook запускає у фоні `AgentVitals.exe hook`, який пише по маленькому файлу стану на сесію в
`sessions\` поруч з exe. **Відключити** прибирає лише записи AgentVitals.

- Пульс б'ється, поки агент працює, а синя крапка блимає, поки він чекає вашого дозволу.
- У поточного ходу видно, скільки він триває («працює · 3 хв»). Сповіщення скаже, коли агент
  закінчить хід, довший за 5 хвилин, або попросить дозволу; обидва налаштовуються чи вимикаються в
  налаштуваннях. *Звук, коли агент чекає дозволу* додає тихий дзвін із двох нот лише до сповіщення
  про дозвіл — типово вимкнений і мовчить, поки вікно сесії активне.
- Список тримає одну висоту — приблизно чотири сесії — і далі прокручується, з тонкою смугою.
- Дві сесії в одній теці показують початок першого запиту замість гілки, щоб їх розрізняти;
  підказка над рядком показує теку, гілку й запит повністю. Око поруч із рядком тарифу ховає
  запити разом із поштою.
- Клацання по сесії там або по її сповіщенню піднімає вікно, де йде сесія, — термінал, VS Code чи
  іншу IDE, — щоб відповісти одразу. AgentVitals шукає його від процесу агента вгору по батьках;
  коли в однієї програми кілька вікон, як у VS Code, виграє те, у заголовку якого тека сесії.
  Піднімається вікно, а не вкладка: якщо вкладок кілька, потрібну оберіть самі. Якщо вікно не
  знайшлося, клацання по сповіщенню відкриває вікно AgentVitals.
- Хід, зупинений Esc, не викликає hook. Про це каже журнал сесії, і сесія одразу переходить у
  простій, а не через 15 хвилин.
- Термінал, закритий без `/exit`, теж не викликає hook. Hook запам'ятовує процес Claude Code, і
  сесія зникає зі списку, щойно цього процесу немає.
- Claude Code читає hooks під час запуску сесії: сесії, відкриті раніше, з'являться після їх
  перезапуску.
- AgentVitals переписує `settings.json` звичайним JSON, тому коментарі в ньому не зберігаються.
  Перед кожною зміною файл копіюється в `settings.json.agentvitals.bak` разом із коментарями.
- Якщо перенести exe, вікно «Агенти» про це скаже — підключіть знову. Перед видаленням exe натисніть
  **Відключити**: інакше Claude Code і далі викликатиме програму, якої вже немає.
- **Codex.** **Підключити** в Codex пише `~/.codex/hooks.json` (або `hooks.json` у
  `$CODEX_HOME`); кожен hook запускає `"AgentVitals.exe" hook codex`. Новий або змінений hook Codex
  запускає лише після підтвердження: відкрийте `/hooks` у Codex один раз після підключення й ще
  раз після перенесення exe. Esc у Codex викликає його власний hook `Interrupt`, тож сесія одразу
  переходить у простій. Сесії Codex видно на вкладці Codex, сесії Claude Code — на вкладці Claude.

## Статистика витрат

Під лімітами вкладки Claude і Codex показують цифри за сьогодні й графік за 30 днів. Для Claude вони
беруться з власних журналів Claude Code у `~/.claude/projects` (разом із субагентами) і читаються
лише на цьому комп'ютері: AgentVitals бере кількість токенів із відповідей моделі й більше нічого не
зберігає. Кожна відповідь рахується один раз — Claude Code пише ту саму відповідь кілька разів, поки
вона надходить.

- **Вартість** — скільки ці токени коштували б за прейскурантом API Anthropic, і на підписці теж.
  Ціни беруться з [офіційної сторінки цін](https://platform.claude.com/docs/en/about-claude/pricing)
  раз на день і зберігаються в `prices.md` поруч із налаштуваннями, тож вартість рахується й без
  мережі. Модель, якої на сторінці ще немає, лишається без ціни, а не із здогадом. Fast mode
  рахується за звичайними цінами.
- **Час роботи** складає відрізки активності; пауза, довша за 30 хвилин, починає новий.
- **Графік** показує вартість, токени (вхід і вихід), кеш (запис і читання) або вартість за
  сімействами моделей (Opus, Sonnet, Haiku, Fable; Astra, Sol, Luna в Codex; інші) — лише ті
  сімейства, що були в ці 30 днів. У режимі кешу в куті написано, скільки кеш заощадив за 30 днів:
  скільки коштували б закешовані токени як звичайний вхід мінус скільки вони коштували.
- **Codex** читає журнали своїх сесій у `~/.codex/sessions` і `archived_sessions` (у `$CODEX_HOME`,
  якщо його задано): по запису на відповідь моделі з кількістю токенів і модель ходу. Вартість — за
  цінами Standard зі [сторінки цін OpenAI](https://developers.openai.com/api/docs/pricing), вони
  зберігаються в `prices-openai.md`; модель без ціни закешованого входу чи запису в кеш платить за
  ці токени як за звичайний вхід.
- У Gemini, Copilot і Cursor статистики поки немає: місце для неї є (`IAgent.Usage`), читача немає.

## Оновлення

Коли ввімкнено *Перевіряти оновлення щодня* (типово), AgentVitals питає в GitHub останній реліз під
час запуску, а потім раз на день, і один раз повідомляє про нову версію. Налаштування →
*Оновлення* → **Перевірити** питає одразу. **Оновити** завантажує `AgentVitals.exe` з релізу,
звіряє його SHA-256 з тим, що публікує GitHub, і відмовляється від файлу, що не збігся. Потім
короткий скрипт чекає, поки програма закриється, кладе новий exe на місце старого — тим самим
шляхом, тож hooks і далі працюють, — і запускає його; якщо заміна не завершилася за 40 секунд,
знову запускається стара версія. Після перезапуску сповіщення називає запущену версію й відкриває її
опис. Попередні релізи й чернетки не пропонуються. Якщо exe лежить там, де не можна писати
(наприклад, у `Program Files`), картка каже про це й веде на сторінку релізу.

## Приватність

- **Входи лише читаються.** AgentVitals ніколи не оновлює токен: Claude Code і Codex роблять це
  самі, а refresh-токен, витрачений кимось іншим, розлогінив би агента. «Диспетчер облікових даних»
  і `state.vscdb` Cursor відкриваються лише на читання.
- **Токен GitHub лишається в git.** Для Copilot AgentVitals читає вхід, який git уже зберігає в
  «Диспетчері облікових даних» Windows, заново перед кожною перевіркою й надсилає його лише на одну
  адресу: `api.github.com/copilot_internal/user`. Він ніколи не записується, не потрапляє в журнал і
  не показується, а в «Диспетчер облікових даних» нічого не пишеться.
- **Вхід Cursor лишається в Cursor.** Він читається з `state.vscdb` Cursor перед кожною перевіркою й
  іде як cookie лише на `cursor.com/api/usage-summary`: переадресації не виконуються, а cookie, які
  ставить Cursor, не зберігаються.
- **Токени моделей не витрачаються.** Запити квот — не виклики моделі, тож перевірка нічого не
  відбирає від ваших лімітів.
- **Куди підключається:** адреси квот із розділу [Агенти](#агенти), status.claude.com,
  status.openai.com, www.githubstatus.com і status.cursor.com, сторінки цін Anthropic і OpenAI раз
  на день і GitHub: `api.github.com` для перевірки релізів (її можна вимкнути) і завантаження релізу —
  лише коли ви натиснули **Оновити**. Більше нікуди — ні власного акаунта, ні телеметрії.
- **Остання відповідь лишається на цьому комп'ютері.** `quota.json` зберігає тариф, пошту акаунта й
  відсотки останньої перевірки; токени не записуються нікуди.
- **Журнали лишаються на цьому комп'ютері.** Статистика зберігає лише кількість токенів. Щоб
  помітити хід, зупинений Esc, кінець журналу живої сесії перевіряється на позначку переривання
  Claude Code. Нічого з журналів не залишає комп'ютер.

## Файли

Усе лежить поруч з exe: `config.json` (налаштування), `quota.json` (остання відповідь про квоти),
`log.txt` (помилки й зміни за два дні), `sessions\` (стани сесій), `prices.md` і `prices-openai.md`
(ціни Anthropic і OpenAI). Якщо тека лише для читання (наприклад, у `Program Files`), вони йдуть у
`%LOCALAPPDATA%\AgentVitals`. Запуск разом з Windows — значення в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Оновлення лишає `AgentVitals.exe.new` поруч з
exe і `agentvitals-update-<pid>.cmd` у `%TEMP%` лише на час своєї роботи.

## Збірка

Потрібен .NET 10 SDK.

    dotnet test AgentVitals.slnx
    powershell -File tools\publish.ps1            # release\AgentVitals.exe, потрібен .NET 10 Runtime
    powershell -File tools\publish.ps1 -SelfContained
    powershell -File tools\make-icons.ps1         # перемалювати src\AgentVitals\app.ico і app.png

Код — чотири проєкти в `src\`, і кожен знає лише тих, що перед ним:

- `AgentVitals.Platform` — виклики Windows, файли, журнал і звуки;
- `AgentVitals.Core` — квоти, витрати, статус-сторінки й живі сесії: модель і контракт, який
  заповнює кожен агент, без інтерфейсу;
- `AgentVitals.Agents` — по теці на агента з тим, що властиве лише йому: квоти, журнал витрат і
  сторінка цін, статус-сторінка, hooks і журнал сесії;
- `AgentVitals` — програма в треї: вікна, рядки, опитування, налаштування й оновлення.

`release\` — тека збірки, у git вона не входить. Публікація релізу на GitHub запускає
[`release.yml`](.github/workflows/release.yml): він проганяє тести на сирцях тега, збирає exe через
`tools\publish.ps1` і додає його до цього релізу.

README — трьома мовами: оригінал — `README.md` (англійською), `README.ru.md` і `README.uk.md`
перекладено з нього. Правка одного йде в усі три.
